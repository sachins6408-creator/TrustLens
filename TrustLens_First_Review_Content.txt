1. PROJECT TITLE
--------------------------------------------------------------------------------
TrustLens – Website Trust Evaluation System using Data Mining


2. INTRODUCTION
--------------------------------------------------------------------------------
In today's digital era, the proliferation of e-commerce, digital services, and online platforms has transformed the way consumers transact and interact. However, this growth has also led to an alarming rise in fraudulent websites, deceptive service providers, and manipulated customer reviews. 

TrustLens is an intelligent, full-stack web application designed to evaluate and determine the authenticity and trustworthiness of websites. By collecting granular, multi-parameter feedback from real users and applying data mining methodologies, TrustLens aims to provide consumers with an objective, transparent, and multi-dimensional trust evaluation before they engage with any online platform.


3. PROBLEM STATEMENT
--------------------------------------------------------------------------------
- Traditional online ratings are overly simplistic, typically relying on a single 1-to-5 star aggregate rating that masks critical operational flaws.
- Existing review mechanisms are vulnerable to fake reviews, biased promotional campaigns, and rating manipulation.
- Consumers lack a centralized, transparent platform to evaluate websites across critical independent dimensions such as payment security, refund policies, and delivery performance.
- There is an absence of intelligent data mining and pattern discovery systems that evaluate website reliability from multidimensional consumer experiences.


4. EXISTING SYSTEM
--------------------------------------------------------------------------------
- General search engines and standalone review blogs.
- Centralized consumer forum websites with unstructured text feedback.
- Basic e-commerce rating widgets that display an unweighted, single average star rating.


5. LIMITATIONS OF EXISTING SYSTEM
--------------------------------------------------------------------------------
- One-Dimensional Scoring: A website with excellent usability but fraudulent refund policies can still hold an artificially high 4-star overall average.
- Lack of Granular Parameters: Users cannot evaluate specific facets like customer support responsiveness or information accuracy separately.
- Vulnerability to Manipulation: Easy for malicious actors to flood simple positive ratings.
- No Advanced Machine Learning Analysis: Existing systems lack clustering and classification to group trustworthy vs. risky websites systematically.


6. PROPOSED SYSTEM
--------------------------------------------------------------------------------
TrustLens proposes a comprehensive website evaluation platform where:
- Websites are indexed across multiple industry categories (E-commerce, Tech, Travel, Services, etc.).
- Consumer evaluations are collected across 9 distinct, dynamic operational parameters rather than a single vague score.
- The system computes granular parameter breakdowns, maintains user search and evaluation histories, and provides role-based moderation.
- A planned Data Mining engine leverages Classification, Clustering, and Association Rule Mining to derive an objective, algorithmic Trust Score (0 to 100) and categorizes platforms into clear trust tiers (Trusted, Moderately Trusted, Risky, Not Rated Yet).


7. OBJECTIVES
--------------------------------------------------------------------------------
- To develop a responsive, modern web platform for searching, exploring, and assessing website credibility.
- To implement a 9-parameter dynamic review system giving consumers fine-grained rating capabilities.
- To prevent review duplication while allowing users to dynamically modify their submitted ratings.
- To implement a robust backend with secure JWT authentication and search history management.
- To design and integrate a Python-based Data Mining framework to process review patterns, classify websites, and compute scientific Trust Scores.
- To provide administrators with moderation tools to ensure review integrity.


8. CORE IDEA / HOW TRUSTLENS WORKS
--------------------------------------------------------------------------------
1. Discovery: Users search for a target website or browse by category on the platform.
2. Parameter Breakdown View: Users inspect the website's profile, including historical ratings across all 9 individual operational parameters.
3. Granular Review Submission: Verified logged-in users submit ratings (scale 1 to 5) for all 9 dynamic parameters along with qualitative comments.
4. Aggregation & Recalculation: The backend server validates parameters, updates individual averages, and updates the website profile in real time.
5. Trust Evaluation (Data Mining): The data mining engine processes multidimensional parameter matrices to assign a normalized Trust Score (0 to 100) and category label.

15. DATA MINING MODULE
--------------------------------------------------------------------------------
- Implementation Status: PLANNED FOR NEXT PHASE
- Technologies: Python 3, Pandas, NumPy, Scikit-learn
- Planned Data Mining Techniques:
  * Classification:
    Using supervised machine learning algorithms (such as Decision Trees / Random Forest / Support Vector Machines) to classify websites into predefined trust classes ('Trusted', 'Moderately Trusted', 'Risky') based on feature vectors composed of the 9 parameter averages and review distributions.
  * Clustering:
    Applying unsupervised learning (such as K-Means or DBSCAN) to group websites with similar multidimensional performance characteristics, revealing hidden patterns and identifying anomaly/outlier websites.
  * Association Rule Mining:
    Applying algorithms (such as Apriori or FP-Growth) to extract behavioral associations between parameters (e.g., finding rules like: "Low Refund Process Rating AND Low Customer Support => High Payment Security Risk").
  * Python Ecosystem Integration:
    - Pandas: Structured tabular data manipulation, feature cleaning, and review aggregation.
    - NumPy: High-performance vector and matrix calculations on rating arrays.
    - Scikit-learn: Building, training, and running the classification and clustering models.


16. TRUST SCORE CONCEPT
--------------------------------------------------------------------------------
- Implementation Status: PARTIALLY IMPLEMENTED (Data Schema & UI Status Badges Defined; ML Calculation Pipeline Planned)
- Concept:
  * A normalized score from 0 to 100 representing the composite reliability of a website.
  * Unlike a raw arithmetic average, the Trust Score integrates weighted parameter criticalities (e.g., Payment Security and Refund Process carry higher risk weightage than Website Usability) combined with data mining classification confidence.
- Trust Categories:
  * Trusted (Score: 75 - 100): High reliability across critical security, refund, and quality parameters.
  * Moderately Trusted (Score: 50 - 74): Average performance, minor concerns in secondary parameters.
  * Risky (Score: 1 - 49): Critical failures in security, refund, or accuracy parameters.
  * Not Rated Yet: New websites with insufficient review volume for statistically significant evaluation.

20. SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
The project follows a decoupled 3-Tier Architecture:

1. Presentation Tier (Client):
   React SPA communicating asynchronously via RESTful JSON APIs. Features Protected Routes, responsive dashboards, and interactive review forms.

2. Application / Logic Tier (Server):
   Express.js API server handling business logic, request validation, JWT authentication middleware, and average score recalculations. Connects to the upcoming Python Data Mining Service.

3. Data Tier (Database):
   MongoDB instance maintaining persistent collections with indexed relationships and unique constraints.


21. DATABASE / MAIN COLLECTIONS
--------------------------------------------------------------------------------
1. users Collection:
   - Fields: name, email (unique), password (hashed), role ('user' | 'admin'), timestamps.
   - Purpose: Manages user credentials, authentication, and authorization privileges.

2. websites Collection:
   - Fields: name, domain (unique), category, description, trustScore, trustCategory, parameterRatings (object with 9 parameters), totalReviews, timestamps.
   - Purpose: Stores indexed website entities and their aggregate rating metrics.

3. reviews Collection:
   - Fields: user (ref: User), website (ref: Website), ratings (9 individual scores: 1-5), comment, overallRating, timestamps.
   - Index: Compound unique index ({ website: 1, user: 1 }) to enforce one review per user per website.
   - Purpose: Records granular user evaluations and qualitative feedback.

4. searchhistories Collection:
   - Fields: user (ref: User), website (ref: Website), searchedAt (timestamp).
   - Purpose: Tracks user viewing and evaluation history for quick access on the dashboard.

26. ADVANTAGES
--------------------------------------------------------------------------------
- Multi-Dimensional Clarity: Evaluates 9 specific facets of service rather than relying on an ambiguous single average.
- Objective Evaluation: Designed to integrate data mining algorithms to eliminate emotional or sponsored review bias.
- Prevents Rating Inflation: Granular parameters force reviewers to consider distinct operational aspects independently.
- User-Centric Experience: Clean single-page application with immediate visual feedback and personal search history.
- Scalable Architecture: Modular MERN stack and decoupled data science pipeline allow seamless scaling.


27. LIMITATIONS
--------------------------------------------------------------------------------
- Cold-Start Dependency: New websites with few or zero reviews will remain in 'Not Rated Yet' status until adequate feedback is collected.
- Manual Input Reliance: Current phase relies on direct user feedback; automated web scraping of external review sources is not yet integrated.
- Data Mining Engine in Transition: The machine learning algorithms are currently in the integration planning phase and will be active in Review 2.
